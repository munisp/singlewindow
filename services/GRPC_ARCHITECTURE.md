# gRPC Architecture — TradeGateway NGSWTP

## Overview

All internal service-to-service communication uses **gRPC over HTTP/2** with Protocol Buffers
for binary serialization. External trader-facing APIs remain REST/JSON for broad compatibility.

## Port Allocation

| Service              | HTTP (REST) | gRPC  | Description                          |
|----------------------|-------------|-------|--------------------------------------|
| declaration-service  | 8081        | 9081  | Core declaration management (Go)     |
| payment-service      | 8082        | 9082  | Mojaloop + TigerBeetle payments (Go) |
| oga-service          | 8083        | 9083  | OGA permit routing (Go)              |
| profile-service      | 8084        | 9084  | Trader profiles + AEO (Go)           |
| risk-engine          | 8090        | —     | ML risk scoring (Python/FastAPI)     |
| sanctions-screener   | 8091        | —     | OFAC/UN/EU screening (Python)        |
| rule-engine          | 8092        | —     | WCO customs rules (Rust/Axum)        |
| tigerbeetle-bridge   | 8093        | —     | Double-entry ledger (Rust/Axum)      |

## Proto Definitions

All protobuf contracts are in `services/proto/`:
- `declarations.proto` — Declaration lifecycle (submit, get, update, stream)
- `payments.proto` — Payment initiation, settlement, drawback
- `risk_engine.proto` — Risk scoring and trader profiles

Generated Go code is in `services/go/proto-gen/` (generated by `protoc-gen-go` + `protoc-gen-go-grpc`).

## gRPC Features Used

### Unary RPC (Request-Response)
Used for: `SubmitDeclaration`, `ScoreDeclaration`, `InitiatePayment`, `GetTraderProfile`

```go
// Client call
resp, err := client.SubmitDeclaration(ctx, &pb.SubmitDeclarationRequest{
    TraderId: 123,
    HsCode:   "8471.30",
    // ...
})
```

### Server-Streaming RPC
Used for: `WatchDeclaration` — real-time status updates pushed to the client
as the declaration moves through customs workflow stages.

```go
// Client receives stream of events
stream, err := client.WatchDeclaration(ctx, &pb.WatchDeclarationRequest{
    DeclarationId: 456,
})
for {
    event, err := stream.Recv()
    if err == io.EOF { break }
    // Handle: status_changed, payment_required, cleared, etc.
}
```

### Health Checking
All gRPC services implement the standard `grpc.health.v1.Health` protocol,
enabling Kubernetes liveness/readiness probes and gRPC load balancer health checks.

```bash
# Check service health with grpcurl
grpcurl -plaintext localhost:9081 grpc.health.v1.Health/Check
```

### Server Reflection
All services enable gRPC reflection, allowing dynamic discovery with `grpcurl`:

```bash
# List available services
grpcurl -plaintext localhost:9081 list

# Describe a service
grpcurl -plaintext localhost:9081 describe ngswtp.declarations.v1.DeclarationService
```

## Regenerating Proto Code

```bash
# Install tools
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest

# Generate for all protos
cd services/proto
protoc --go_out=../go/proto-gen --go_opt=paths=source_relative \
       --go-grpc_out=../go/proto-gen --go-grpc_opt=paths=source_relative \
       *.proto
```

## Dapr Integration

In production, Dapr sidecars handle service discovery, mTLS, and retries:

```yaml
# Dapr component: service invocation
apiVersion: dapr.io/v1alpha1
kind: Component
metadata:
  name: declaration-service
spec:
  type: bindings.grpc
  metadata:
    - name: url
      value: "declaration-service:9081"
    - name: maxRecvMsgSize
      value: "4194304"  # 4MB
```

## Production Considerations

1. **mTLS**: All gRPC connections use mutual TLS in production (via Dapr or Istio)
2. **Load balancing**: Client-side load balancing via gRPC-Go built-in resolver
3. **Deadlines**: All RPCs set context deadlines (5s for scoring, 30s for payments)
4. **Retries**: Exponential backoff with jitter for transient failures
5. **Tracing**: OpenTelemetry spans propagated via gRPC metadata headers
